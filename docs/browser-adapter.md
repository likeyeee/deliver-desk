# 浏览器适配

桌面版通过 Electron 自有窗口操作可见网页；CLI 使用 Playwright。两者根据配置选择 `BossAdapter` 或 `ZhaopinAdapter`，共享任务控制、历史去重、发送登记和不确定结果处理。

## 智联招聘

2026-09-11 在应用内浏览器检查了智联登录、搜索、地区、筛选、列表与独立详情，并完成一笔获授权的通用岗位投递；成功弹窗与网站求职反馈中的同一职位记录一致。后续增加了智联自定义设置页的可见控件检查。连续投递和异常分支使用隔离的合成网页验证。

- 登录入口为 `https://passport.zhaopin.com/login`，点击 `.zppp-panel-normal-bar__img` 切到微信扫码。保存的登录需等待页面恢复；职位页 `.c-login__top__name` 可见且非空才确认登录。
- 从 `/jobs/?pageMode=search` 搜索，通过 `.query-sug__input` 和搜索按钮提交关键词，核对输入框及 URL 中的 `kw`。地区选择使用 `.filter-region-box` 内的弹窗、城市名输入框与唯一匹配的 `.s-option__label`，不能从 BOSS 城市编号推算智联编号。当前页面不提供“全国”。
- 筛选限定在各自的 `.filter-select-box`，选择后重新读取网站的选中标记。行业与职位类别按“大类 > 子类”逐列展开，或用“大类 > 不限”选择整个大类；不把展开菜单当作完成筛选。关键词、城市和筛选变化后等待列表实际更新并稳定；不能把旧卡片或超时当成新结果。
- 列表卡片没有公开职位链接。先读取 `.job-card` 的岗位与公司，再选择卡片，等待右侧 `.job-detail-modules` 的标题、公司、选中卡片和详情链接同步更新；切换卡片后链接仍是旧值则停止。职位 ID 只从页面提供的详情链接读取，不调用隐藏接口或读取框架内部状态。
- 独立详情使用 `/jobdetail/<id>.htm`；网站求职反馈中的旧 `jobs.zhaopin.com/<id>.htm` 链接归一到同一 ID。历史键加 `zhaopin:` 前缀，避免与 BOSS ID 冲突；追踪参数不保存。
- 发送前核对 `.summary-planes__title`、`.company-info__name`、规范 URL 和唯一“立即投递”按钮。原生点击前与实际点击事件中再次核对，目标变化时阻止提交。已有“继续沟通”“已投递”或“已申请”状态跳过。
- 自定义与 AI 模式先在 `https://i.zhaopin.com/im/greeting/setting` 切到“招呼语”和“自定义”。使用 `.phrase-modal textarea`、保存按钮、`greeting-item-*` 条目标识及默认单选图标核对。只编辑本应用创建且内容未被修改的条目，复用一条，不覆盖用户已有模板。限制按网站输入框的 UTF-16 长度校验为 500，保存和默认切换均核对原文；重新加载设置页后才刷新岗位详情。保存及默认按钮的实际点击仍绑定此前读取的条目与输入内容。
- 每次投递前重读当前默认条目及原文，详情重载后还需确认 JD 未变化。任务完成、停止或失败时恢复运行前默认招呼；状态先保存在本机，强制退出后可恢复未完成的设置。用户在运行中另选的默认条目不被覆盖，恢复无法确认时显示待处理。
- 先登记 `sending`，再点击一次“立即投递”。只有同一目标详情出现可见的 `.deliver-greeting-modal__title` 成功回执、非空招呼且主按钮变为“继续沟通”，才记录 `sent` 及网站实际发送的招呼。关闭结果弹窗后继续下一岗，定制招呼原文不一致时记录 `partial` 并保留期待正文及实际回执，不补发。
- 只读核验会进入网站提供的求职反馈地址，在“投递成功”标签中核对 `.ji-item` 的职位链接、标题、公司和“成功投递”状态。“继续沟通”按钮单独出现不能证明简历送达；定制招呼还需核对该岗位成功回执中的期待原文，只有求职反馈时保留待核对。

智联登录使用独立的 `persist:zhaopin` 分区，BOSS 继续使用原来的 `persist:boss`。窗口、弹窗和导航限定到其所属平台，网站仍没有应用 preload 或 Node.js 权限。合成测试覆盖会话隔离、原生搜索与筛选、预览零发送、连续投递、去重、旧详情、旧列表、目标变化及隐藏回执；网站布局变化仍可能需要重新适配。

## BOSS 页面与定位

- 搜索页为 `/web/geek/jobs`。提交关键词后同时检查输入框与 URL，等待结果或明确空结果，再选择城市和筛选项。
- 城市入口加载时可能先显示占位文字。已选城市读 `.cur-city-label`；其他城市从弹窗字母分组选择。
- 每个筛选项在自己的菜单内按可见文字定位，并核对选中标签及 URL 条件，避免命中职位卡片中的同名标签。
- 职位 ID 来自 `/job_detail/<id>.html`；持久化 URL 不保留 `securityId` 等追踪参数。
- 列表工资可能是私有区字体字符。继续读取独立详情；无法解析的薪资遵循配置中的 `unknown_salary`，不猜测数字。

## 发送与回执

“立即沟通”可能只建立会话，或同时触发平台招呼。`platform` 模式到此结束；`custom` 模式继续验证目标并发送配置文案。

简易沟通弹窗不足以验证目标时，跟随页面实际提供的“消息”链接打开完整聊天页。先检查已选会话能否核对目标；需要选择联系人时，按公司定位，同公司有多人则同时匹配职位详情中的招聘者姓名。姓名必须位于同一联系人条目中、公司文字之前，不能借用其他条目或消息预览里的名字。随后仍通过当前会话的职位链接或“查看职位”弹窗核对职位 ID、公司和岗位。同公司同名仍不唯一时停止，公司或姓名本身不构成发送依据。

“立即沟通”会打开网站的简易聊天窗口。导航上的未读数字会把入口名称变成“消息 7”等形式，因此按可见链接的实际地址识别完整聊天入口，要求 HTTPS、准确的网站域名和 `/web/geek/chat` 路径，并确认目标地址唯一。无需点击被弹窗遮住的导航。聊天内的竞争力 PK 卡片属于消息内容，不点击其“查看详细分析”按钮。

没有职位链接的会话只打开一次“查看职位”核对，桌面版在后台关闭该核对页，保持聊天页显示。核对结果绑定当前编辑器、联系人信息和职位卡片；这些节点变化、页面跳转或选择其他联系人时失效并停止发送。输入文字、收到新消息和回执更新不会触发重复开页。

桌面鼠标点击先检查控件在视口内的可见区域。中心被网页浮层遮住时，选择仍能命中同一控件的露出区域；全部被遮挡或禁用时停止，不强制点击。发送前后的目标、草稿和回执检查仍然生效。

原生点击等待目标页面完成渲染帧，再次核对位置仍属于同一控件，避免 macOS 新页面在获得焦点但尚未绘制时漏掉输入；等待期间布局或焦点变化则停止点击。

浏览器页占满应用内容区域，保留进度、暂停/停止、日志和返回入口。网页出现水平溢出时，根据实际内容宽度缩小该页；扩大窗口后恢复到正常字号上限。各标签的缩放独立，页面加载、切换和窗口变化时重新检查，尺寸测量不会无限等待页面。鼠标坐标先按 CSS 像素核对同一控件，再按当前页面缩放换算为原生视图坐标；不额外乘屏幕像素密度。

确认发送需要：编辑器清空、己方消息原文匹配、同一气泡具有送达/已读/发送成功回执。当前网站己方原文结构为 `.message-item.item-myself .text-content`；外层 `.text` 还包含回执，不能直接用于原文全等比较。

回执不明确记为 `partial` / `unknown`，阻止自动重发。“只读核对送达”重新检查原记录中的消息和目标，确认后更新同一条历史，不输入文字、不新增尝试。

## 兼容与诊断

自动回复从当前可见页面的消息入口进入“全部”会话，滚动 `.user-list-content` 读取网站渲染的联系人行。未读数字只作展示；实际是否待回复由最后一条消息的方向和类型决定。每行用当前 DOM 标记及姓名、公司、消息预览重新核对，列表复用节点或改变内容后重新定位。同名同公司同预览的不同条目也逐一检查。选择后核对联系人姓名、公司及职位，通过该会话的“查看职位”读取公开职位 ID；正文生成与发送沿用会话绑定和回执验证。只读扫描不会调用模型或点击发送，也不会关闭其他标签中的草稿。

自动回复的合成测试覆盖未读及已读待回复、已回复但仍有角标、列表滚动与节点变化、附件和草稿、生成时的新消息、缺失回执、每日额度及关闭中断。网站真实布局变化仍需单独验证，合成测试通过不等同于完整收件箱的实站验收。

遇到验证页、网站限制、导航空白或目标不明确时停止。诊断保存地址路径、允许的搜索参数、控件结构和截图；原始 HTML、Cookie 和令牌不进入诊断 JSON。

2026-09-08 的 Electron 实站验证覆盖登录恢复、搜索、城市及经验筛选、职位详情、自动发送、重新打开后的只读送达核验和历史去重。首次发送曾因旧消息选择器漏识别回执，修正后通过只读核验完成确认。尚未逐项验证全部筛选、长列表滚动和所有聊天布局。

原 Playwright 专用会话仍出现过 `code=37` / `about:blank`，不能把合成页面测试通过视为该路径的实站验证。适配改动先使用 `tests/test_browser.py` 中的合成页面复现，再由使用者在自己的账号上小范围确认。
